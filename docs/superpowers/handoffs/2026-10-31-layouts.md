### How it's built (architecture)

- `src/components/layout/app-shell.tsx` keeps all layout-independent effects and dialogs, and renders `shellFor(layout)` from `src/components/layout/shells/index.ts`.
- **The page never remounts on a switch.** The routed page and its scroller (`<main class="app-scroll">`) live in a persistent node, which `shells/persistent-page.tsx` portals into each shell's slot. Scroll position and focus are restored on the move.
- **Shell contract.** Every shell in `shells/*-shell.tsx`, with its parts in `shells/<name>/`, must do all of these:
  - Provide the Home header slot via `RouteHeaderSlotContext`.
  - Publish `--shell-left-inset`, `--shell-right-inset` and `--shell-bottom-inset` via `shells/insets.ts`, so the jump pill, selection toolbar and toasts clear its chrome.
  - Give the dial a correct "visible" signal; non-Sidebar shells nest a `SidebarProvider`.
  - Include a pop-out-to-floating button.
  - Keep Settings, Downloads, playlists and the account menu (`UserProfile`) reachable.
- **Switching:**
  - `src/lib/theme/layouts.ts` holds `LAYOUT_ORDER`, names, `nextLayout` and `dialTipOpen`.
  - `src/components/theme/layout-flip.tsx` holds `flipTo` and `cycleOnKey` (Ctrl+L, which is ignored in inputs, while the first-launch picker is open, and while a dialog is open).
  - `src/components/theme/turntable-dial.tsx` is the dial.
  - The layout is stored as `layout` in the `ytm-looks` zustand store. Upgraders stay on Sidebar.
- **Floating mini player:** works in every layout. In non-Sidebar layouts, player mode `"floating"` is the on/off switch and the built-in player stays visible. The "Side card" and "Bottom bar" options only show in Sidebar.
- **Shared helpers:** `shells/compact.ts` (`useCompact`, 1100px), `shells/insets.ts` (`useHeight`), `player-chrome.ts` (`COVER_RADIUS`), and `shells/player-colour.ts` (`usePlayerStyle`).

## How the work was done (method)

- **Process:**
  - Brainstorm, then a written spec. A builder subagent checks the spec, then the user approves it.
  - Next, a plan, mockups and user approval.
  - Then **subagent-driven development**. This uses the superpowers skills at `C:\Users\sdand\.claude\plugins\cache\claude-plugins-official\superpowers\7.0.0\skills\subagent-driven-development\`, and its scripts are `task-brief`, `review-package` and `sdd-workspace`.
- **Per task:**
  - Write a brief file: the plan's Global Constraints, the task text, plus "carried" notes from earlier tasks.
  - Dispatch one implementer (opus), which commits and writes a report file.
  - Run `review-package BASE HEAD`, then dispatch a task reviewer (opus). It gives two verdicts, spec and quality.
  - Run fix rounds by resuming the same implementer with SendMessage, each followed by a scoped re-review (sonnet).
  - Log everything in the ledger, including a `Ruling:` line for each decision.
  - Never run two implementers at once.
- **Finally:** one whole-branch review (opus), one fix dispatch, and a scoped re-review.
- **Usage limits:** when an agent dies on a usage limit, resume **the same agent** with SendMessage after the reset; its work is saved. Overnight, an hourly CronCreate "watchdog" did this.
