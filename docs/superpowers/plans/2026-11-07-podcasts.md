# Podcasts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Full YouTube Music podcast support in Porchlight: a Podcasts tab, show pages, resume and played state, next-episode playback, downloaded episodes, and optional SponsorBlock sponsor skipping.

**Architecture:** Episodes are ordinary `QueueTrack`s carrying an `episode` field, so the existing player, video mode, speed and sleep timer work unchanged. One persisted zustand store owns progress and played state. A new `lib/innertube/podcasts.ts` parses YouTube Music's podcast pages; the audio engine gains small episode branches (resume, mark played, next episode, no music autoplay).

**Tech Stack:** Tauri 2, React 19, TypeScript, TanStack Router + Query, zustand persist, vitest, `@tauri-apps/plugin-http`.

**Spec:** `docs/superpowers/specs/2026-11-07-podcasts-design.md`

## Global Constraints

- No em or en dashes in any UI copy.
- Page heading is exactly "Podcasts" (no name after it).
- Nav order: Home, Explore, Podcasts, Search, Library, Downloads, Rewind.
- Started = 30 seconds listened. Played = position ≥ 95% of duration, or within the last 30 seconds, or marked by hand.
- SponsorBlock: episodes only, `skipSponsors` defaults to `false`, credited in Settings > About per CC BY-NC-SA.
- Episodes never reach Rewind, Last.fm, or music autoplay (auto-radio).
- Free accounts: no downloads (existing `useCanDownload`); playback follows existing free-playback rules.
- Any new screen needs an HTML mockup with real data approved by the user before it is built (Task 0).
- Every task adds a line to `docs/superpowers/handoffs/2026-10-31-full-project.md` in the same commit.
- Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Leave `src-tauri/Cargo.toml` line-ending noise out of commits.
- Tests: vitest, node env by default; `// @vitest-environment jsdom` for DOM tests; no JSX in tests.

## Review Focus

1. **App closed mid-episode** (crash, quit, tray quit): reopening must resume within a few seconds of where it stopped. Pinned in Task 2 (`saves on pause and on quit`).
2. **Episode with no known duration** (still loading, or a live/premiere stub): must never be marked played or show "NaN min left". Pinned in Task 2 (`unknown duration never counts as played`).
3. **Last episode of a show ends** (nothing newer, or everything after it already played): playback stops; no music radio starts. Pinned in Task 3 (`no next episode stops`).
4. **SponsorBlock offline or erroring**: playback continues untouched, no toast, no retry storm. Pinned in Task 7 (`fetch failure skips nothing`).
5. **Switching to video mode mid-episode**: continues at the same spot and keeps saving progress. Pinned in Task 3 (`video mode keeps position`).

### Task 2: Episode progress store

**Files:**
- Create: `src/lib/store/episodes.ts`, `src/lib/store/episodes.test.ts`, `src/lib/store/show-sort.ts`, `src/lib/store/show-sort.test.ts`

**Interfaces:**
- Consumes: `QueueTrack`, `isEpisode` (Task 1)
- Produces:
  - `type EpisodeState = { position: number; duration?: number; played: boolean; updatedAt: number; track: QueueTrack }`
  - `useEpisodesStore` (zustand persist, name `"ytm-episodes"`, version 0) with `byId: Record<string, EpisodeState>` and:
    - `record(track: QueueTrack, position: number, duration?: number): void` (ignores non-episodes; sets `played` when the played rule is met; never un-marks)
    - `markPlayed(track: QueueTrack): void`, `markUnplayed(videoId: string): void` (clears played and position)
  - `episodeStatus(s: EpisodeState | undefined): "new" | "started" | "played"`
  - `minutesLeft(s: EpisodeState): number | null` (null when duration unknown)
  - `inProgress(byId): EpisodeState[]` (started, not played, newest `updatedAt` first)
  - `STARTED_SEC = 30`, `PLAYED_FRACTION = 0.95`, `PLAYED_TAIL_SEC = 30`
  - In `src/lib/store/show-sort.ts`: `useShowSortStore` (persist `"ytm-show-sort"`): `byShow: Record<string, "newest" | "oldest">`, `setOrder(showId, order)`, `orderOf(showId): "newest" | "oldest"` (default `"newest"`), and `localFollows: string[]` with `addLocalFollow` / `removeLocalFollow` (fallback when following on YouTube fails)

- [ ] **Step 1: Write failing tests:**

  - `mark unplayed clears progress`: markPlayed then markUnplayed → `"new"`, position 0.
  - `songs are ignored`: record a non-episode → `byId` unchanged.
  - `pick up lists newest first and skips played`.
  - `remembers the order per show` (set CreepCast oldest; Unsubscribe still newest).
  - `saves on pause and on quit`: the persisted storage has the latest position after `record` (use the store's storage mock, as `sleep-timer.test.ts` does).
