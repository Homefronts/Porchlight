# Layouts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship four new layouts (Gatefold, Index, Crate, Panels) that work with every look and every screen, switchable on a whim with a turntable dial, Ctrl+L and a record-flip.

**Architecture:**
- **One outer shell, swappable arrangements.** `AppShell` keeps everything that's layout-independent: keyboard, floating sync, dialogs, picker, notices. It renders one of five arrangement components, each picked by the look store's `layout`.
- **Shared slots.** Every arrangement places the same pieces: the router `<Outlet/>`, the nav, a player, and the dial. Switching layouts never remounts the page or the player state.
- **The dial and Ctrl+L** both call one `setLayout`, which runs a flip transition.

**Tech Stack:** React 19, TypeScript, Tailwind v4, TanStack Router, zustand persist, vitest, Tauri 2.

**Spec:** `docs/superpowers/specs/2026-10-30-layouts-design.md`. Mockups: `docs/superpowers/specs/2026-10-27-themes-mockups/liner-layouts.html` and https://claude.ai/artifact/27xaUPVn1bEUDMimjTYB4N.

## Global Constraints

- Layout ids: `"sidebar" | "gatefold" | "index" | "crate" | "panels"` (the existing `LayoutId`, stored as `layout` in `ytm-looks`).
- Dial order (notches): Sidebar, Gatefold, Index, Crate, Panels. Ctrl+L goes to the next in this order and wraps around.
- **Everyone upgrading from 1.0 stays on Sidebar** until they switch. The last layout is remembered.
- Any look works on any layout; every screen is reachable in every layout.
- The floating mini player is available in every layout.
  - In Sidebar, today's behaviour is unchanged.
  - In the other layouts the built-in player stays visible while floating is on, and closing the floating window just closes it.
- Crate's crate browsing is Home only. Index's contents page is Home only. All other screens keep their usual content inside the layout's frame.
- Copy (no em or en dashes):
  - tip: "Turn this to change layouts."
  - theme-file offer: "This look was made for {Layout}. Switch to {Layout}?"
  - Gatefold empty state: "Nothing playing yet"
  - Index empty strip: "Nothing on the tape"
- Reduced motion: the flip becomes a fade; the dial turn and turntable spin are off.
- The dial click sound is off by default.
- Classic + Sidebar stays pixel-identical to 1.0. Check every task touching shared UI with a before/after run-app screenshot pair.
- vitest runs `src/**/*.test.ts` in node; use `// @vitest-environment jsdom` for DOM tests; no JSX in tests.
- Run-app checks use `.claude/skills/run-app/`, with CDP app-only screenshots (never the full desktop).
  - The dev build has its own app id, so the installed app keeps running.
  - Afterwards, restore the `ytubic-plus` URL scheme to the installed exe, and delete only the dev data dirs.
- Build at full speed. Don't push or tag. Releases are user-gated.

## Review Focus

1. **Switching mid-song.** Playback, position, queue and the floating window all continue untouched. Test in Task 2: switching `layout` never remounts the player store or the router outlet. Checked live in Task 9.
2. **Ctrl+L while typing** in the search box or a rename field types an "l" and doesn't switch. Test in Task 3 (`shouldCycleOnKey`).
3. **A half-typed search or a scrolled long list survives a layout switch,** because the page component isn't remounted. Test in Task 2, plus a live check in Task 9.
4. **A narrow window** (about 800 px wide) never hides navigation, Settings or the player in any layout: each falls back to its compact form. Live check in each layout task.
5. **A theme file naming Crate** imported while on Sidebar asks once and switches only on yes; picking that look later never changes the layout. Test in Task 3.
